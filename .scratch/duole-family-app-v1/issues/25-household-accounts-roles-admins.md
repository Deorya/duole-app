# 实现家庭账号、成员、三级身份与多管理员

Status: needs-triage

Type: HITL

User stories covered: 13–18, 21

## Parent

[多乐守护 App 与机器人端接入 V1 PRD](../PRD.md)

## What to build

在 Engineering V1 稳定机器人合同之上，引入 Family Product 的云端/远程家庭账号模型：一户
绑定一台机器人和一位主要照护对象，支持人数不设上限的独立成员账号、管理员/照护成员/
关注成员身份标签以及多位平权管理员。身份只用于家庭理解，实际能力授权留给后续细粒度权限
切片。

## Acceptance criteria

- [ ] 家庭模型明确约束一户、一台机器人、一位主要照护对象，并拒绝当前不支持的多照护对象归因。
- [ ] 成员使用独立账号和稳定 member identity，不提供共享家庭密码。
- [ ] 家庭成员数量无产品硬上限；分页、邀请、接受、离开和停用在大成员集下保持有界。
- [ ] 每位成员可标记为管理员、照护成员或关注成员，身份标签不自动授予完整功能权限。
- [ ] 任意成员可被提升为管理员，管理员人数无上限且彼此平权，不存在隐藏超级管理员。
- [ ] 家庭始终至少保留一名管理员；最后一名管理员不能直接离开、降级或删除自己。
- [ ] 管理员拥有成员与权限管理入口；其他身份默认不能管理家庭。
- [ ] App 完成登录、家庭选择/绑定、成员列表、邀请和身份变更的端到端流程。
- [ ] 机器人绑定与家庭账号之间使用可撤销的远程 authorization，不把云账号凭据下发为机器人本地长期万能 token。
- [ ] 成员新增、移除、身份变化和绑定变化产生稳定审计事件，并向权限切片提供 actor/context。
- [ ] 并发管理员修改、重复邀请、过期邀请、被移除在线会话和最后管理员约束测试通过。
- [ ] 账号、家庭、App UI、远程 gateway/relay 与机器人授权的安全/隐私架构完成联合评审。

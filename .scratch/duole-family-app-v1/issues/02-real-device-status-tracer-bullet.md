## What to build

交付第一个可演示的端到端 tracer bullet：Android Engineering App 通过 TLS 调用公网关，
公网关通过 owner-only 本机 IPC 进入正式机器人运行时内的领域门面，再调用现有同一个
Device Status 服务，最终在 App 页面显示一项真实版本或设备状态。

本切片允许使用明确标识的预置短期工程测试凭据；不实现正式配对，也不触发运动、媒体或
正式日程写入。

## Acceptance criteria

- [x] Android 页面从真实机器人返回一项 Device Status，包含状态、观测时间、新鲜度和稳定原因码。
- [x] 网络链路使用 TLS，响应符合已冻结 envelope，并贯穿同一个 request ID。
- [x] 公网关只通过私有 IPC 调用正式运行时门面，不直接 import ROS、打开设备文件或连接日程数据库。
- [x] 门面复用正式对象图内已存在的 Device Status 实例；测试能证明没有创建第二套 provider/cache。
- [x] IPC 检查父目录和 socket 的 owner、权限、非 symlink、peer identity、协议版本、消息大小和 deadline。
- [x] provider 超时、缺失或异常映射为稳定 unknown/unavailable 响应，不能导致网关崩溃或假绿。
- [x] App 能区分 `REAL` 与 `MOCK_NO_MOTION`，未知模式时不显示可执行运动能力。
- [x] 单元、IPC 集成、provider contract 和 Android consumer 测试覆盖正常及失败路径。
- [x] 切片可在不启动真实运动的条件下独立演示，并记录 App、网关、运行时和 schema 版本。

### 2026-08-18 Agent Brief

## Agent Brief

**Category:** enhancement

**Summary:** 贯通 Android Engineering App、TLS 公网关、owner-only 本机 IPC 与正式机器人
运行时中的同一个 Device Status 对象图，展示真实电池状态且在所有失败路径上明确 fail closed。

**Current behavior:**

App API v1 已冻结机器人身份、版本、能力与电池状态的机器可读合同，Python provider 和 Dart
consumer 也能共同验证该合同及 fixture。正式产品运行时已经装配并持有唯一的
`DeviceStatusRuntimeBundle`，其中 `DeviceStatusService` 与电池 source/cache 同时服务现有语音和
运行时入口。但当前没有 Android Engineering App 页面、TLS App gateway、运行时领域门面或二者
之间的私有 IPC，因此真实状态还不能从机器人到达 App。

**Desired behavior:**

Android Engineering App 使用冻结的 Dart consumer 调用真实机器人的只读 v1 接口，并显示电池
健康、摘要、稳定原因码、观测时间与新鲜度。公网关终止 TLS、验证最小工程测试凭据和请求元数据，
随后只通过受限本机 IPC 查询正式运行时内的领域门面。领域门面必须复用已装配的
`DeviceStatusRuntimeBundle.service` 及其现有 provider/cache；任何 IPC、provider、版本或模式异常
都返回冻结合同允许的 unknown/unavailable，而不是崩溃、绕过正式对象图或制造成功数据。

**Key interfaces:**

- App API v1 operations `getRobotIdentity`、`getVersions`、`getCapabilities` 与
  `getBatteryStatus` — 响应和失败都必须通过已冻结 envelope，并保持来站请求的 request ID。
- `DeviceStatusRuntimeBundle` 与 `DeviceStatusService` — App 读路径只能注入和复用正式产品运行时
  已有实例；不得再次调用产品 Device Status 组合根或建立第二套 provider/cache。
- `AppGatewayDomainFacade` — 运行时内的 transport-neutral 只读边界，将 battery observation 映射为
  冻结 DTO，保留观测时间、新鲜度和稳定原因码，不暴露 ROS、设备文件或内部诊断细节。
- Owner-only local IPC — 有界、版本化、带 deadline 的请求/响应协议；客户端和服务端共同校验父目录
  与 socket 的 owner、权限和非 symlink 属性，服务端还校验 peer identity。
- Android Engineering status screen — 使用生成的 Dart 类型消费真实响应，区分 `REAL`、
  `MOCK_NO_MOTION` 和未知模式；只有明确 `REAL` 才允许把运动能力呈现为可执行。

**Acceptance criteria:**

- [ ] 在不启动真实运动、媒体或日程写入的情况下，Android 页面能通过 TLS 显示真实机器人电池
      状态、观测时间、新鲜度和稳定原因码。
- [ ] 身份、版本、能力和电池响应均通过冻结的 v1 provider/consumer 验证；同一个 request ID
      贯穿 HTTP、IPC、领域查询和最终 envelope。
- [ ] 网关进程不能 import ROS 适配器、打开设备文件或连接日程数据库，只能调用私有 IPC client。
- [ ] 对象身份测试证明领域门面持有正式产品运行时注入的同一个 `DeviceStatusService`、battery
      provider/source/cache，且 App 链路不会触发第二次 Device Status 组合。
- [ ] IPC 测试覆盖父目录/socket owner 与 mode、symlink 拒绝、peer identity、协议版本、空帧、
      malformed/deep/oversized frame、deadline、慢客户端、断连和干净关闭。
- [ ] provider 缺失、超时、抛错、无观测、陈旧观测及 IPC 不可用都映射为稳定
      unknown/unavailable 与 reason code；网关保持可用且绝不返回假 `ok`。
- [ ] `REAL`、`MOCK_NO_MOTION` 与未知模式在 Android consumer 中有测试；未知模式和不兼容 API
      major 只保留诊断读取，不呈现任何可执行运动能力。
- [ ] 单元测试、同进程 facade 测试、跨进程 IPC 集成测试、TLS gateway/provider contract 测试和
      Dart/Android consumer 测试覆盖正常及失败路径，并可由一个重复执行的验证入口运行。
- [ ] 演示证据记录 App、gateway、runtime 与 schema 版本、测试设备标识和 request ID；工程测试凭据
      明确标为短期预置凭据，不被描述为正式配对。

**Out of scope:**

- 正式配对、令牌轮换、账号/家庭会话、公网云中继或云通知。
- WebSocket 事件 replay、事故投影、媒体、音频、日程写、导航、遥控及任何真实运动。
- 为 live video、teleop 或 schedule write 返回可用或成功占位数据。
- 新建平行 Device Status 服务、provider/cache、直接 ROS/硬件读取路径或第二个产品运行时入口。

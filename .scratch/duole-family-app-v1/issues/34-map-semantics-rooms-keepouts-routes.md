# 实现地图级房间、禁行区与巡逻路线配置

Status: needs-triage

Type: HITL

User stories covered: 184–185, 196–199

## Parent

[多乐守护 App 与机器人端接入 V1 PRD](../PRD.md)

## What to build

让现场用户把已保存地图转成可供后续房间导航和巡逻使用的产品地图。Android 只提交房间
大致中心、禁行区几何和由已验证房间组成的路线；导航板根据活动地图和代价地图修正、验证、
版本化并持久化这些配置。App 不直接写 YAML、墙体、任意导航目标或底层参数。

## Acceptance criteria

- [ ] 房间、禁行区、巡逻路线和充电桩锚点全部绑定稳定 `map_id` 和 map revision；切图不会复制或混用另一地图的坐标数据。
- [ ] 现场用户输入唯一房间显示名称并点选大致中心；导航板将其修正到安全可通行区域，生成稳定 room ID 和验证结果，不要求用户手画房间多边形。
- [ ] 导航板无法找到安全区域、地图 revision 已变化或定位/代价地图不可信时拒绝保存，不把原始点伪装成 verified room。
- [ ] 巡逻路线只能由当前地图的已验证房间组成，支持排序和稳定 route ID；首版不开放任意坐标巡逻点。
- [ ] 用户可圈定地图级禁行区；导航板校验几何、边界和 revision 后生成版本化 keepout，不开放墙体绘制、充电桩点选、地图上传或导航参数修改。
- [ ] 房间目标、路线和禁行区新增/修改/删除要求 `maps.manage` 和有效现场地图管理会话；重命名地图、删除非当前地图和回收站恢复不要求现场会话。
- [ ] 配置写入采用 optimistic revision、request ID、TTL 和 idempotency；并发修改返回当前 revision，不静默覆盖。
- [ ] 删除地图时关联语义配置一起进入回收站并可恢复；永久删除后清除配置，审计只保留必要元数据而不保留家庭平面图。
- [ ] Android 在地图上区分大致输入、导航板修正候选、已验证和拒绝状态；低分地图仍允许配置，但展示质量提示。
- [ ] 使用真实手动生成地图完成房间目标到达可行性、禁行区生效、路线引用、revision 冲突、切图隔离和回收恢复 HIL/REAL 验收。

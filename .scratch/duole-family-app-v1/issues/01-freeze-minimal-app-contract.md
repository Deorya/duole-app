## What to build

由 Windows App、机器人网关和运行时负责人联合冻结第一个可运行只读切片的共享合同，并建立
后续 REST、事件、媒体和遥控 schema 都能复用的兼容性工具链。完成后，两端应能从同一份
机器可读合同生成模型、验证 fixture，并在版本不兼容时一致地关闭写能力。

首个冻结范围只覆盖通用 envelope、请求追踪、机器人模式、版本、能力和一项真实设备状态；
未经过技术预研的媒体、日程写和遥控字段不得以假数据进入冻结合同。

## Acceptance criteria

- [x] 联合评审并冻结 REST 版本策略、成功/错误 envelope、request ID、server time、TTL、幂等键和 revision 规则。
- [x] 冻结 `REAL`、`MOCK_NO_MOTION`、状态健康、未知枚举及版本不兼容时的 fail-closed 行为。
- [x] 冻结最小机器人身份、版本、能力和单项 Device Status schema，并为每种响应提供有效 fixture。
- [x] Python provider 模型与 Dart consumer 模型由同一机器可读合同生成或验证，禁止两端手工维护平行字段。
- [x] Provider 与 consumer 契约测试能在 CI/本地重复运行，并能检测字段删除、语义改变和 enum 复用。
- [x] 未实现能力明确返回 unavailable/unsupported，不得为了客户端页面显示而提供假成功值。
- [x] 评审记录包含 App、网关、运行时、测试 owner 和冻结日期；破坏性变更必须升 major。
- [x] 共享冻结产物成为双方唯一机器可读合同来源，Markdown 仅保留说明和决策背景。

## Agent Brief

**Category:** enhancement

**Summary:** 将已批准的最小 App 合同固化为 Python provider 与 Dart consumer 共用的机器可读
合同，并建立可重复执行的兼容性验证。

**Current behavior:**

当前 Windows 交接包只有建议性 Markdown API 合同。仓库中没有这组 App-facing DTO 的唯一
机器可读来源，也没有可以同时约束 Python provider 和 Dart consumer 的 fixture、生成/验证
入口及兼容性测试，因此两端仍可能独立解释字段和枚举。

**Desired behavior:**

最小只读切片由一个版本化的机器可读合同定义。Python 与 Dart 模型均从该合同生成或接受其
验证；相同 fixture 在两端得到一致结果。破坏性字段或语义变更必须提升 major，未知模式或
未知安全相关枚举必须 fail closed，未实现能力必须明确返回 unavailable/unsupported。

**Key interfaces:**

- App API v1 machine-readable contract — 唯一事实源，仅包含本次冻结的最小范围。
- `SuccessEnvelope<T>` 与 `ErrorEnvelope` — 统一 schema version、request ID、server time 和
  稳定错误语义。
- Request metadata — 定义 TTL、幂等键和 revision 的存在条件及验证规则。
- `RobotMode`、机器人 identity/version、capability 与一项 Device Status DTO — 支持真实值、
  新鲜度和明确 unavailable/unknown，不允许假绿。
- Provider/consumer contract validation entrypoints — 在机器人端和 Windows App 端使用同一组
  fixture 验证兼容性。

**Acceptance criteria:**

- [x] 机器可读合同覆盖且只覆盖本工单批准的最小范围，并具有明确版本和破坏性变更规则。
- [x] 通用成功/错误 envelope、request ID、server time、TTL、幂等和 revision 规则可自动验证。
- [x] `REAL`、`MOCK_NO_MOTION`、未知模式及安全相关未知枚举的 fail-closed 行为有契约测试。
- [x] 机器人身份、版本、capability 与一项真实 Device Status 均提供有效及失败 fixture。
- [x] Python provider 与 Dart consumer 从同一合同生成或验证模型，并消费同一组 fixture。
- [x] 自动化测试能识别字段删除、必填性变化、enum 语义复用和不兼容 major。
- [x] 未实现能力只能表达为 unavailable/unsupported，fixture 中不存在用于点亮页面的假成功。
- [x] 冻结产物记录 schema 版本、冻结日期及 App、网关、运行时和测试责任角色。

**Out of scope:**

- mDNS 发现、正式配对和令牌生命周期。
- 事件 replay、事故、媒体、音频、日程写、导航、遥控及其他运动合同。
- 实现工单 02 的网关、机器人运行时 IPC 或 Android Device Status 页面。
- 为尚未实现的能力添加占位成功数据。

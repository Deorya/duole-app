# 多乐守护 App PRD

Status: `ready-for-human`

版本：`requirements-freeze-v1`

日期：`2026-08-17`

## 1. 产品定义

多乐守护是 DUOLE 居家陪护机器人的移动端接入层。长期产品帮助家属远程了解照护状态、
管理日程、接收安全事件、进行音视频陪伴并执行有限机器人控制。近期先交付
`Engineering V1`：一款在同一局域网内供工程师连接、操作和诊断真实机器人的 Android App。

App 不是新的机器人“大脑”。它只通过可信网关提交命令、展示机器人运行时给出的事实，
不得在手机端复制任务仲裁、重算安全概率、绕过本地隐私锁或直接控制 ROS Topic。

## 2. 为什么分成两层

当前仓库已经形成日程、对话、设备状态、导航、安全、跌倒、人员视觉和隐私控制的统一
工作流，但尚不存在真实 App transport、账号系统、局域网媒体网关或云端通知服务。

如果首版同时建设云端账号、九方媒体、推送、短信、iOS 和全部家庭权限，工程师会很晚才
拿到可操作机器人。反之，如果只写一个临时遥控器，又会丢失家庭产品的权限、隐私和信息
架构。因此本 PRD 同时保留：

- 近期可验收的 `Engineering V1`；
- 后续演进的 `Family Product`。

## 3. 用户与场景

### 3.1 Engineering V1 用户

- 机器人端、导航、视觉、语音和 App 联调工程师；
- 与机器人处于同一受控局域网；
- 需要快速发现设备、看到真实状态、操作任务、验证媒体和导出诊断证据；
- 接受工程状态和明确错误，但不能接受无反馈按钮、假成功或失联后继续运动。

### 3.2 Family Product 用户

- 一位主要照护对象的家属与照护者；
- 家庭成员人数不受产品硬上限限制；
- 需要在不制造持续焦虑的前提下，知道是否有事情需要关注；
- 需要日程管理、远程现场、通话、事件通知和有限控制；
- 不需要 ROS、进程名、模型分数或开发诊断。

### 3.3 家庭模型

```text
一户家庭
├── 一台 DUOLE 机器人
├── 一位主要照护对象
└── 多位家庭成员
    ├── 身份：管理员 / 照护成员 / 关注成员
    └── 权限：按成员逐项配置
```

当前日程未具备多用户归属，视觉也不能可靠识别具体身份，因此同一机器人不承诺同时服务
多位照护对象的独立日程与安全归因。

## 4. 产品原则

1. **诚实状态：** “没有告警”不能显示成“老人一定平安”。
2. **本地优先：** 机器人本地隐私锁、急停和安全抑制高于 App 命令。
3. **任务而非 Topic：** 导航、巡逻、回充均使用有状态、有结果、可取消的任务语义。
4. **断链停车：** 遥控必须是短租约和持续保活，失去输入即停止。
5. **单一事实源：** 日程、状态、任务和事件由机器人领域服务拥有，App 不建立平行真相。
6. **概率不冒充结论：** App 展示后端给出的观察、关注和紧急语义，不重新解释原始分数。
7. **默认安静：** 平时界面克制；真正需要处理时明确提升层级。
8. **工程能力可移除：** 诊断能力通过构建模式隔离，不泄漏到家庭产品。

## 5. Engineering V1 目标

### 5.1 目标

- Windows 团队能够构建 Android APK，并在受控局域网连接真实 DUOLE 机器人。
- 工程师不需要理解 ROS 图即可发现设备、查看能力并执行受支持任务。
- 任何 App 操作均有接受、运行、成功、失败、取消或不可用的明确结果。
- 实时画面、环境音、喊话、通话和手动遥控形成单手机闭环。
- 网关复用现有日程与设备状态，不新建平行数据库和状态机。
- 断线、超时、故障和安全抢占在 UI 与接口中可观察。
- 工程模式能够导出足以复现问题的脱敏诊断包。

### 5.2 成功标准

| 指标 | Engineering V1 目标 |
|---|---|
| 首次连接 | 同网设备可发现；自动发现失败时可用 IP 连接 |
| 命令反馈 | 每次操作在 UI 中产生稳定请求 ID 和终态 |
| 停止安全 | 松手/断链先产生零速或停止请求；真车停止仍须满足机器人端既有 `<=1 s` 红线 |
| 状态真实性 | 离线、陈旧、不可用和隐私关闭不得显示为正常 |
| 重连 | 重连后恢复快照并补拉遗漏事件，不重复执行旧命令 |
| 数据一致性 | App 与机器人语音读到同一份日程和任务状态 |
| 诊断 | 关键失败能导出时间、版本、请求 ID、状态与错误码 |

这些目标是 App 验收门槛，不代表当前机器人硬件链已经全部通过真机验收。

## 7. Engineering V1 非功能需求

### 7.1 安全与可靠性

- App 不直接访问 DDS/ROS 2，不直接发布 `/cmd_vel`。
- 所有写命令包含稳定请求 ID、发送时间、TTL、操作者和幂等键。
- 网关拒绝过期、重复、版本不兼容、权限不足和状态门未通过的命令。
- UI 只有收到机器人确认后才显示成功；发送成功不等于动作成功。
- 所有长任务可取消，安全事件可抢占普通任务。
- 遥控输入必须有序列号与 watchdog；旧包、乱序包和失联不能维持非零速度。

### 7.2 性能目标

以下是 Engineering V1 的测试目标，需以真实局域网和真机数据调整：

| 项目 | 目标 |
|---|---|
| 普通 API 响应 | 局域网 P95 `<=500 ms` |
| 状态/任务事件到 UI | P95 `<=1 s` |
| 直播首帧 | P95 `<=3 s` |
| 遥控端到端视频延迟 | 目标 `<=500 ms`，超过 `800 ms` 禁止继续遥控 |
| 摇杆松手到网关零速意图 | `<=300 ms` |
| 真车停止 | 遵守机器人端现有 `<=1 s` 安全红线 |
| WebSocket 重连 | 网络恢复后 `<=5 s` 开始重连并补拉 |

### 7.3 可访问性

- 正文和状态文字满足 WCAG 2.2 AA 对比度；点击目标不小于 48×48 px。
- 支持系统字体缩放至 200%，关键动作不依赖颜色单独表达。
- 横竖屏切换不得改变摇杆安全语义；来电、锁屏和后台立即释放遥控。

### 7.4 可移植性

- 客户端业务层不硬编码 ROS topic、Action 名称或机器人 IP。
- OpenAPI/事件 schema 可生成 Dart 模型。
- 媒体实现、设备发现和安全存储通过端口隔离，允许 Windows 团队替换插件。
- Android 为 E1 验收平台；iOS 代码路径保留但不计入首版完成状态。

## 8. Family Product 目标范围

Family Product 在 Engineering V1 之上增加：

- 手机号验证码、新设备登录和生物识别；
- 一户一机器人一照护对象、无限家庭成员和平权多管理员；
- 身份与功能权限分离的细粒度授权；
- 公网安全接入、可靠推送和 60 秒未查看短信兜底；
- 多人同时观看、互斥喊话和机器人加八位家属的九方视频通话；
- 机器人屏幕双格、四宫格、九宫格及无屏幕时语音降级；
- 高风险操作再认证、全管理员通知与审计；
- Android/iOS 双端完整验收；
- 本文已确认的记录保留、通知自定义和隐私交互。

家庭产品仍不包含：多人照护对象归因、医疗诊断、生命体征、家庭聊天、持续录像、App
截图/录屏、机构工作台、付费商城和底层地图编辑。

## 9. 依赖与主要风险

| 风险 | 当前事实 | 对策 |
|---|---|---|
| App 网关不存在 | 仓库没有 HTTP/WebSocket ingress | 先冻结接口和适配层，不让客户端依赖 ROS |
| 媒体网关不存在 | 当前没有可供 App 播放的 WebRTC 服务 | 单独做相机/音频/硬件编码 spike |
| 音频资源冲突 | 麦克风、ASR、TTS、喊话和通话共享硬件 | 冻结音频仲裁状态机，真实验证回声与抢占 |
| 手动遥控安全链缺口 | 当前 App teleop 尚未实现，真车 stop 仍是红线 | 短租约、watchdog、固定上限、真实断链测试 |
| 导航真机成熟度不齐 | 软件映射较完整，部分动作与恢复未全部验收 | capability gate；未通过的按钮禁用并解释 |
| 日程更新缺口 | 现有主线以创建/查询/删除为主 | 在同一领域服务中新增版本化更新/启停接口 |
| 视觉身份限制 | 人员观测不是身份识别 | UI 不称检测到的人为特定老人 |
| 工程能力泄漏 | 工程师需要原始诊断，家庭用户不需要 | 独立 build flavor、路由和编译时能力表 |

## 10. 完成定义

Engineering V1 只有在以下条件同时满足时才可称为完成：

1. [ACCEPTANCE_AND_HANDOFF.md](ACCEPTANCE_AND_HANDOFF.md) 中所有 P0 软件验收通过；
2. 真机运动、断链停止和媒体链有可复现证据；
3. App 不把 mock、缓存、发送成功或进程存在显示为真实成功；
4. 接口 schema、错误码、功能清单和实际 APK 一致；
5. 工程诊断包不含令牌、原始音视频或无关个人信息；
6. Windows 开发环境、构建步骤、Android 签名和回滚方式已写入交付说明。

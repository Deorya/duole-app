# 多乐守护数据、隐私与权限规格

Status: `ready-for-human`

本文件定义家庭产品目标，并明确 Engineering V1 的简化方式。它是产品与工程约束，不替代
上线前的法律、隐私和安全评审。

## 1. 适用边界

| 层次 | 身份模型 | 连接范围 | 本期实现 |
|---|---|---|---|
| Engineering V1 | 本地工程师显示名 + 单机器人绑定令牌 | 受控局域网 | 是 |
| Family Product | 手机号账号 + 家庭成员 + 设备会话 + 细粒度权限 | 经安全远程服务 | 未来 |

Engineering V1 不实现手机号、短信、生物识别、家庭邀请或云端账号，但 API 和数据模型不得
把“工程师即超级管理员”写死到业务实体中。

## 2. 家庭与成员模型

```text
Household（单个家庭）
├── Robot（V1 一台）
├── CareSubject（V1 一位主要照护对象）
├── Member（数量不设产品上限）
│   ├── governance_role：管理员 / 照护成员 / 关注成员
│   └── grants：逐项功能权限
└── EmergencyRecipientPolicy（至少一名有效接收者）
```

### 2.1 三种治理身份

| 身份 | 含义 | 强制能力 |
|---|---|---|
| 管理员 | 共同治理家庭、成员和授权 | 管理成员与权限、查看权限审计 |
| 照护成员 | 建议用于频繁照护的显示模板 | 无；业务权限仍逐项授权 |
| 关注成员 | 建议用于只看重要状态的显示模板 | 无；业务权限仍逐项授权 |

管理员人数不设上限；一个家庭可以让全部成员都是管理员。管理员地位平等，不存在永久的
“创建者超级管理员”。业务权限不与身份绑定：管理员也可能没有直播或遥控权限，关注成员
也可以被单独授予日程编辑权限。

为避免家庭失去治理能力，系统要求至少保留一名有效管理员。最后一名管理员不能退出、被
移除或降级，除非先提升另一名成员。该约束只保护家庭管理能力，不限制管理员总数。

## 3. 权限键

建议权限键采用稳定、可版本化的字符串；客户端只能根据服务端 grants 渲染，不能按身份
名称推断能力。

| 权限键 | 允许的能力 | 风险级别 |
|---|---|---|
| `household.members.manage` | 邀请、移除成员和改变治理身份 | 高 |
| `household.permissions.manage` | 授予/撤销业务权限 | 高 |
| `household.audit.read` | 查看家庭权限与高风险操作审计 | 中 |
| `status.read` | 查看家庭首页和机器人状态 | 低 |
| `events.read` | 查看安全与设备事件详情 | 中 |
| `events.notifications.receive` | 接收事件通知 | 中 |
| `live.view` | 查看实时画面与环境音 | 高 |
| `live.talk` | 使用按住喊话 | 高 |
| `live.call` | 发起/加入全双工通话 | 高 |
| `teleop.control` | 手动遥控 | 极高 |
| `robot.stop` | 停止运动任务或遥控 | 高、安全方向 |
| `navigation.start` | 前往房间、立即巡逻 | 高 |
| `dock.start` | 结束冲突任务并发起回充 | 高 |
| `patrol.schedule.manage` | 创建、编辑、启停定时巡逻 | 高 |
| `schedule.read` | 查看日程和执行结果 | 中 |
| `schedule.manage` | 新增、编辑、启停、删除日程 | 高 |
| `map.label.manage` | 修改房间展示名、选择已验证巡逻点 | 中 |
| `privacy.disable_visual` | 请求关闭视觉监护 | 高、安全方向 |
| `privacy.enable_visual` | 在无本地锁时请求开启视觉监护 | 极高 |
| `records.read` | 查看允许范围内的会话和操作记录 | 中 |

`robot.stop` 采用宽授权：任何具有该权限的成员都可停止，不要求其持有任务或遥控权。停止
仍记录操作者，但不增加会拖延停止的再认证步骤。

### 3.1 建议模板而非硬绑定

邀请时可提供“管理员”“日常照护”“仅关注”权限模板，以降低配置成本。模板展开后应允许
管理员逐项修改，保存的是具体 grants，而不是运行时根据模板名称计算权限。

### 3.2 权限计算规则

```text
有效权限 = 当前成员显式 grant
         ∩ 当前设备 capability
         ∩ 当前运行状态安全门
         ∩ 本地隐私策略
```

权限允许不代表当前可执行。例如成员拥有 `teleop.control`，但画面冻结或定位异常时仍必须
拒绝。拒绝响应需区分 `PERMISSION_DENIED`、`CAPABILITY_UNAVAILABLE`、`SAFETY_GATE_BLOCKED`
和 `LOCAL_PRIVACY_LOCKED`。

服务端是权限判定者；隐藏按钮只是界面便利，绝不是安全边界。

## 4. Engineering V1 的身份与授权

- 首次启动输入工程师显示名，生成不可变 `installation_id`。
- 机器人本地生成一次性配对码；成功后颁发绑定 `robot_id + installation_id` 的短范围令牌。
- 令牌只包含 Engineering V1 所需的本地 scopes；不得提供任意 shell、任意 ROS Topic 或
  绕过安全门的能力。
- 令牌保存在 Android 系统安全存储中，不写日志、不导出到诊断包。
- 取消配对同时清除本地令牌并在网关撤销对应会话。
- 网关可列出和撤销已配对工程设备；撤销在活动媒体、遥控和任务控制流中尽快生效。
- `REAL` 与 `MOCK_NO_MOTION` 由机器人端配置和签名状态给出，工程 App 不能切换。

Engineering V1 可以把全部已配对工程客户端映射到一个受限的 `engineer_local` policy，但接口
返回仍采用 scopes，便于未来替换成家庭成员授权。

## 5. Family Product 账号与会话（未来）

### 5.1 登录

- 手机号一次性验证码作为账号入口；验证码短时有效、限速且不可写入日志。
- 设备会话使用可撤销 access/refresh token，并绑定设备安装实例。
- 系统生物识别用于本机解锁敏感会话或高风险操作，不把生物特征上传服务器。
- 新设备登录向现有管理员发通知，并在成员页显示设备与最后活动时间。

### 5.2 首次绑定

- 扫描机器人二维码，二维码包含稳定机器人 ID、短期配对会话和设备公钥指纹。
- 机器人本地必须再次确认，避免仅拿到照片的人远程绑定。
- 绑定完成后，发现广播和 IP 地址不能替代设备身份。

### 5.3 高风险操作再认证

以下操作建议要求近期登录或本机生物识别：成员移除、管理员变更、权限变更、开启视觉、
撤销所有设备、导出家庭审计。直播、喊话、通话、遥控是否每次再认证由家庭策略决定，但
进入后台或会话超时后必须重新验证。

再认证不得阻挡“停止机器人”或“关闭视觉”这两个安全方向的动作。

## 6. 隐私控制优先级

从高到低：

```text
机器人本地硬件/物理控制
  > 本地隐私锁
  > 机器人安全策略和能力门
  > 家庭权限策略
  > App 用户操作
```

- 老人在机器人本地开启隐私锁后，所有远程直播、视觉遥控和视觉驱动任务立即结束。
- 远程不能绕过或静默解除本地隐私锁；页面只提示“需在机器人本地解除”。
- 获授权成员可以请求关闭视觉；关闭需等待媒体和运动实际停止确认。
- 开启直播无需老人逐次批准，但机器人端必须有持续、可感知的提示。
- 提示链故障时不得悄悄观看；媒体能力返回不可用或显著降级。
- 打开直播默认包含环境声音，并在 App 和机器人端清楚表达。
- 机器人端提示的具体实现应覆盖视觉和听觉中的至少一种持续方式，并为感官障碍保留替代。

## 7. 数据分类与最小化

| 类别 | 示例 | 默认处理 |
|---|---|---|
| 账号与家庭 | 手机号、成员名、身份、设备会话 | 仅 Family Product；加密存储，最小展示 |
| 权限与审计 | grant、撤销、操作者、时间、目标 | 结构化保存，不含令牌 |
| 机器人状态 | 电量、网络、能力、更新时间 | 当前事实为主；历史按必要性聚合 |
| 日程 | 标题、时间、重复、确认结果 | 正式日程服务单一事实源 |
| 安全事件 | 等级、来源、事故生命周期、处理状态 | 保存结构化事实，不默认保存媒体 |
| 视觉事实 | 人数、覆盖、链路健康 | 不做身份推断，不形成活动轨迹 |
| 媒体会话元数据 | 参与者、开始/结束、降级原因 | 保存元数据，不保存内容 |
| 音视频内容 | 直播、环境音、喊话、通话 | 实时传输，不在产品端录制或留存 |
| 对话内容 | 原始语音、ASR 转写、闲聊文本 | 家庭 App 不读取、不展示、不建历史 |
| 工程诊断 | 版本、错误码、请求 ID、延迟摘要 | 脱敏后按用户主动导出 |

产品不收集生命体征，不提供医疗诊断，不将人员检测自动绑定到特定照护对象。

## 8. 留存策略（Family Product）

已确认的目标策略：

| 记录 | 留存时间 | 说明 |
|---|---:|---|
| 设备状态与媒体会话元数据 | 30 天 | 不含音视频内容 |
| 日程执行结果 | 180 天 | 包含完成、稍后、跳过、未确认 |
| 安全事件结构化记录 | 180 天 | 不包含默认录像/录音 |
| 权限变更与高风险操作审计 | 1 年 | 用于家庭治理和安全追溯 |
| 原始音视频 | 0 天 | 不录制、不存储 |
| 原始对话与转写 | 0 天 | App 不采集、不展示 |

删除应覆盖主存储、搜索索引和常规备份生命周期，并在隐私政策中解释备份延迟。达到期限后
自动删除或不可逆匿名化，不能只在 UI 隐藏。

Engineering V1 的本地事件缓冲和日志保留由容量测试确定，应短、可配置且自动轮转；诊断
导出仍遵循最小化。不能因为是工程版就无限保存音视频或凭据。

## 9. 审计模型

建议统一审计记录：

```json
{
  "audit_id": "aud_...",
  "occurred_at": "2026-08-17T10:42:12.238+08:00",
  "household_id": "hh_...",
  "robot_id": "rb_...",
  "actor": {"type": "member", "id": "mem_...", "display_name": "A"},
  "action": "permission.grant",
  "target": {"type": "member", "id": "mem_..."},
  "request_id": "req_...",
  "result": "succeeded",
  "reason_code": "user_confirmed",
  "metadata": {"permission": "live.view"}
}
```

必须审计：

- 成员邀请、加入、移除、身份变化；
- 权限授予与撤销；
- 新设备登录、令牌撤销、首次机器人绑定；
- 直播、喊话、通话的会话开始/结束及参与者（不含内容）；
- 遥控、导航、巡逻、回充和停止的发起与终态；
- 视觉开关、本地隐私锁投影和远程开启拒绝；
- 日程创建、编辑、删除及版本冲突；
- 诊断导出。

审计记录不可被普通成员修改。管理员可以查看家庭权限与高风险操作，但日志中的手机号、IP
等敏感字段需掩码；家庭管理员不是系统数据库管理员。

## 10. 通知隐私与治理

- 通知锁屏文案默认最小化，如“家中机器人有一条紧急事件，请打开查看”，详细内容在解锁
  后展示。
- 每名成员可自定义事件类型、渠道、声音和免打扰。
- 至少一名有效成员必须接收紧急事件；关闭最后一名时要求先选择替代者。
- 60 秒短信兜底只基于“获授权接收者是否打开事件详情”，不以推送送达回执冒充已查看。
- 同一事故的重复模型帧不得反复发送短信；按 `incident_id` 聚合。
- 家庭成员之间不提供 App 内聊天或处置记录，避免建立不完整的协商真相。

## 11. 媒体与系统录屏边界

App 不提供截图、录音、录像或云端回放按钮，也不承诺阻止手机操作系统或外部摄像设备的
截图/录屏。产品应：

- 在隐私说明中明确系统级录屏不受 App 完全控制；
- 不把系统截图上传服务端；
- 使用平台提供的敏感窗口保护仅作为可选策略，并评估是否会妨碍工程诊断；
- 记录媒体会话元数据，不记录媒体内容；
- Family Product 中向机器人端和在场通话成员持续展示参与者状态。

## 12. 数据模型草图

```text
Household 1 ── * Member
Member    1 ── * Grant
Household 1 ── 1 CareSubject
Household 1 ── 1 RobotBinding
Robot     1 ── * DeviceSession
Robot     1 ── * Schedule
Robot     1 ── * Job
Robot     1 ── * Incident ── * Event
Robot     1 ── * MediaSession ── * Participant
Household 1 ── * AuditRecord
```

标识符必须稳定且不可由展示名派生。成员、房间、机器人和照护对象改名不改变 ID。事件原始
来源 ID 与产品投影 ID 都应保留关联，以便诊断但不泄漏到不需要的家庭界面。

## 13. 安全实现基线

- 局域网广播只用于发现，任何广播字段都不可信。
- 使用加密连接；首次本地配对固定机器人设备身份，后续证书或密钥变化需重新确认。
- 令牌最小权限、可撤销、定期轮换；日志和崩溃报告统一脱敏。
- 所有写请求含操作者、设备会话、TTL、幂等键和请求 ID。
- 服务端对权限、能力、安全门和本地隐私逐次校验，不能信任客户端传来的角色。
- 媒体信令授权与 REST 会话绑定；猜到房间 ID 不能加入媒体。
- 遥控租约和 watchdog 在机器人端执行，手机进程不是最终安全边界。
- 家庭产品上线前完成威胁建模、渗透测试、依赖审计、隐私政策和适用法域评审。

## 14. 产品明确不拥有的数据

- 老人的连续活动轨迹或基于人脸的身份历史；
- 原始对话内容、语音转写和闲聊摘要；
- 生命体征、病历、诊断或服药依从性医学结论；
- 持续环境录音、持续录像和安全事件默认录像；
- 家庭成员电话协商内容；
- App 之外的系统截图与录屏文件。

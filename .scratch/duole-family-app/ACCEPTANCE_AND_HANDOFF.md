# 多乐守护 Engineering V1 验收与 Windows 交接

Status: `ready-for-human`

本文只定义后续开发、验证和交接方式。本轮交付没有创建 App 工程、可点击原型、APK、网关
进程或机器人配置，也没有在当前机器人板上安装移动端开发环境。

## 1. 交付边界

### 1.1 Engineering V1 必须交付

- 同一局域网内连接一台真实 DUOLE 机器人；
- Android 工程 APK，可由 Windows 团队重复构建；
- RK3588 上的 `duole-app-gateway` 与必要媒体适配；
- 发现、手动 IP、一次性配对和本地工程师会话；
- 首页、状态、事件、现场、环境音、喊话、通话、手动遥控；
- 房间导航、立即/定时巡逻、回充、停止、地图只读；
- 正式日程服务上的查询、新增、编辑、删除、启停、重复和确认结果；
- 视觉隐私状态与安全关闭；
- 工程诊断、脱敏导出、错误码和请求关联；
- 真实断线、媒体、音频仲裁和运动停止证据。

### 1.2 Engineering V1 明确不交付

- 公网远程连接、App 被杀死后的通知保证；
- 手机号账号、家庭邀请、细粒度家庭权限、推送或短信；
- iOS 安装包和 Mac 真机验收；
- 多手机同时观看、机器人加 8 位家属的九方通话；
- 家庭聊天、事件工单、医疗能力、生命体征；
- App 内截图、录音、录像、回放；
- 机构运维、批量设备管理或开发 shell；
- 底层地图、禁行区、充电桩位姿和导航参数编辑。

上述能力是未来 Family Product 范围时，应继续遵守当前文档中的家庭模型、权限和设计约束，
但不得纳入 E1 工期或用占位按钮冒充完成。

## 4. 开发环境约束

### 4.1 Windows/Android

- 在 Windows 10/11 的受支持版本上使用 Flutter stable channel 与 Android Studio/SDK。
- JDK、Flutter、Dart、Gradle、Android Gradle Plugin、NDK（如媒体插件需要）由项目文件锁定，
  不依赖开发者全局“最新版本”。
- 首个工程提交需包含版本管理说明、依赖锁文件和一条可重复的 clean build 命令。
- Android application ID、`engineering`/`family` flavor、debug/release 签名明确隔离。
- `engineering` flavor 有显著水印和工程模式；`family` flavor 在编译时移除诊断路由和危险
  测试能力，而不是只用隐藏菜单。
- 局域网、mDNS、相机/麦克风、通知和前台服务权限按最小范围申请，并设计拒绝后的页面。
- token 使用 Android Keystore 封装；不得放入源码、普通 SharedPreferences 或构建日志。

### 4.2 iOS 保留但不验收

Flutter domain/application 层不得依赖 Android 专有类型；发现、安全存储、生命周期和媒体使用
可替换端口。Windows 无法完成 iOS 正式签名与真机验收，后续必须在 Mac/Xcode 环境单独完成，
不得把“代码可编译推测”写成 iOS 已支持。

### 4.3 机器人端

- 新网关必须通过正式启动/监督入口装配，端口、证书、日志和版本有明确配置。
- App 不要求开发者临时关闭现有语音、视觉或安全服务后才能工作。
- 网关不可直接写正式日程数据库，不可打开第二个相机 owner，不可直接向 App 暴露 ROS/DDS。
- 任何 mock 必须通过 capability 和全局 UI 显示 `MOCK_NO_MOTION`。

## 5. 先做技术预研，再冻结接口

以下 spike 是进入完整页面开发前的硬门槛：

| Spike | 最小问题 | 通过证据 | 失败时处理 |
|---|---|---|---|
| `SPK-01` 相机共享 | 能否不争抢 owner 取得实时 RGB | 现有视觉继续运行 + 手机实帧 + 资源指标 | 改共享边界，不启动第二 owner |
| `SPK-02` 编码 | RK3588 能否稳定硬编并满足延迟 | 30 分钟温度/CPU/帧率/延迟曲线 | 降分辨率/帧率并公布 capability |
| `SPK-03` 音频 | 环境音、喊话、通话与 ASR/TTS 能否仲裁 | 真实扬声器/麦克风录屏及状态日志 | 先修单 owner/AEC，不做假通话 |
| `SPK-04` teleop | 运动侧是否有唯一 owner 和独立 watchdog | 断 App/断 Wi-Fi 后车轮停止测量 | 未通过则 E1 禁用真实遥控 |
| `SPK-05` 日程 | 正式服务能否安全增加 revision/update | 语音与 API 并发冲突测试 | 在领域层补用例，不让网关直写表 |
| `SPK-06` 事件 | 来源能否稳定映射 ID、seq 和补拉 | 重启/断线/重复/游标过期测试 | 先建投影存储与重建策略 |
| `SPK-07` 配对 | TLS、设备身份和 Keystore 路径可行 | 抓包无明文凭据 + 撤销测试 | 不允许退回明文控制 |
| `SPK-08` mDNS | 目标手机/路由器是否稳定发现 | 多路由器、休眠恢复、手动 IP 降级 | 保留手动 IP，不弱化身份校验 |

每个 spike 输出一页结论：环境、代码 commit、测量方法、数据、限制、决定和接口影响。

## 6. 建议实施顺序

### Phase 0：合同与骨架

- 关闭上述 spikes；
- 冻结 OpenAPI、事件 schema、错误码、capability keys 与版本策略；
- 建立 Flutter 双 flavor、网关服务骨架、契约生成和 CI；
- 完成真实/模拟模式的端到端 tracer bullet。

退出条件：App 能发现、配对、拉取真实快照、接收一条真实事件，并把 request ID 贯穿到诊断。

### Phase 1：状态、首页与事件

- 实现快照、WS 重连/补拉、陈旧状态、首页模块排序和消息中心；
- 实现设备状态、活动 incident 和真实错误态；
- 断线时禁用写操作，不让缓存冒充实时。

### Phase 2：任务、地图与日程

- 实现地图/房间、导航、巡逻、回充、停止和统一阶段组件；
- 在正式 Schedule 服务实现 revision CRUD、启停、确认状态和定时巡逻；
- 验证语音端与 App 使用同一事实源。

### Phase 3：媒体与音频

- 单手机 WebRTC 画面与环境音；
- 机器人持续提示、隐私锁联动；
- 互斥喊话和一对一全双工通话；
- 真实硬件编码、AEC、ASR/TTS 仲裁和故障降级。

### Phase 4：手动遥控

- 只有 Phase 3 视频健康和 `SPK-04` 通过后开放；
- 实现短租约、有序意图、双 watchdog、固定安全上限和独立 stop；
- 逐项完成生命周期、断网、冻结、隐私和安全抢占真车测试。

### Phase 5：诊断、硬化与 APK

- 脱敏诊断、性能基线、长稳、故障注入、无障碍和小屏/字体检查；
- 完成依赖/凭据检查、release build、签名、校验和回滚说明；
- 形成逐需求追踪表与已知限制。

阶段顺序可并行开发，但遥控真车开关不能早于媒体健康和运动安全门验收。

## 7. 验收环境与证据

每轮正式验收记录：

```text
App commit / version / flavor / APK SHA-256
Gateway commit / version / API schema version
Robot runtime commit / configuration / REAL or MOCK_NO_MOTION
Robot serial / camera / mic / base firmware
Android phone model / OS version
Router/AP / Wi-Fi band / network topology
Test date / tester / observer
```

每个用例保留：前置条件、操作、期望、实际、结果、request/job/session ID、时间戳、必要日志、
手机录屏和真车外部视频。视频必须避免收录无关家庭成员和真实私人场景。

### 7.1 证据等级

| 等级 | 含义 | 可证明什么 |
|---|---|---|
| `SCHEMA` | 契约/单元测试 | 字段和纯逻辑 |
| `SIM` | 模拟 provider/mock 底盘 | UI、错误和状态编排 |
| `HIL` | 真实板卡/传感器，运动隔离 | 媒体、设备链和控制边界 |
| `REAL` | 真实手机、网络和可运动机器人 | 端到端安全与产品完成 |

P0 页面可以先用 SIM 开发，但媒体真实链、音频仲裁、运动停止、隐私关闭和任务成功必须有
对应 HIL/REAL 证据。`MOCK_NO_MOTION` 永远不能证明真车导航或遥控成功。

### 8.4 手动遥控与停止

所有 REAL 用例在清空的封闭区域、抬轮架或分阶段限位环境执行；现场准备可触达的硬件急停，
测试人员不站在运动方向。先 HIL 后低速落地。

| ID | 场景与通过条件 | 证据 |
|---|---|---|
| `AT-TOP-01` | 视频/控制/定位/安全任一门不健康时不能进入或取得控制 | HIL |
| `AT-TOP-02` | 按住才有非零意图，松手立即释放；服务端确认后 UI 才显示已停 | REAL |
| `AT-TOP-03` | App 后台、锁屏、来电、进程杀死分别触发机器人侧归零 | REAL |
| `AT-TOP-04` | Wi-Fi 关闭、AP 断电、丢包和 WS 半开连接均由 watchdog 归零 | REAL |
| `AT-TOP-05` | 视频冻结或延迟超过 800 ms 时自动停并锁定 | REAL/HIL |
| `AT-TOP-06` | 乱序、重复、过期、超范围 intent 被丢弃，不能延续运动 | HIL |
| `AT-TOP-07` | 本地隐私、安全事件、急停或高优先级 owner 抢占并说明原因 | REAL |
| `AT-TOP-08` | 协议级并发只能产生一个租约；松手后不保留所有权，也没有接管申请状态 | HIL/SIM |
| `AT-TOP-09` | 机器人端固定低速/加速度上限，App/抓包篡改归一值不能提高 | REAL + 审查 |
| `AT-STOP-01` | 无遥控权也能调用停止；重复调用幂等并取消 App 持有运动任务 | REAL |
| `AT-STOP-02` | 从触点松开/断链到真实车轮停止 `<=1 s`，记录多轮最差值 | REAL |
| `AT-STOP-03` | 停止未确认时 App 保持红色锁定并要求现场核查，不恢复控制 | HIL |

## 10. 非功能验收

### 10.1 性能

| 指标 | 目标 | 测量起止 |
|---|---:|---|
| 普通 API P95 | `<=500 ms` | App 发出至解析完整响应 |
| 状态/任务事件到 UI P95 | `<=1 s` | 来源发生至界面稳定展示 |
| 直播首帧 P95 | `<=3 s` | 点击查看至真实首帧呈现 |
| 遥控视频延迟目标 | `<=500 ms` | 真实场景动作至手机显示 |
| 遥控禁用阈值 | `>800 ms` | 超阈值自动停止，不允许继续 |
| 松手到网关零速意图 | `<=300 ms` | 触点释放至网关接受归零 |
| 松手/断链到真车停止 | `<=1 s` | 触点/链路事件至车轮停止 |
| 网络恢复后开始重连 | `<=5 s` | OS 报网络可用至新连接尝试 |

每项至少报告样本数、P50、P95、最大值、测试网络和失败样本；只给平均值不算通过。

### 10.2 稳定性

- 首页状态/事件连接持续 24 小时，无无界内存、句柄或磁盘增长。
- 媒体连续 2 小时，记录温度、帧率、音频、重协商和资源占用。
- 导航/巡逻/回充按安全环境各执行足够轮次并报告成功率与每个失败原因。
- 网络抖动、网关重启、媒体进程重启和机器人领域服务短暂不可用均有可恢复结果。
- 稳定性轮次和门槛由 spike 数据冻结；不得只报告“运行了一段时间”。

### 10.3 可访问性与适配

- Android 目标最低/主流版本和至少小、中、大三种手机尺寸；
- 系统字体 100%、150%、200%，关键文字/按钮不截断；
- TalkBack 可读页面标题、状态、按钮、表单错误、事件等级和任务阶段；
- 深色模式、减少动态、横竖屏、分屏、系统返回和权限拒绝；
- 关键点击目标至少 48×48 px，文本和非文本状态达到既定对比要求；
- 不只靠红/黄/绿区分安全状态。

## 11. 安全与隐私验收

至少执行：

- 局域网扫描者无法读取状态、地图、事件或媒体；
- mDNS 伪造不能让 App 在无警告下控制另一设备；
- 配对码重放、暴力尝试、token 重放和已撤销 token 被拒绝；
- 抓包中无明文 token、配对码、音视频或控制指令；
- 所有写操作服务端校验 scope、TTL、幂等、capability、安全门和本地隐私；
- 未知 enum、畸形 JSON、超大 payload、快速重放不会崩溃或开放能力；
- media/teleop session ID 被猜中也不能越权加入；
- 诊断包、日志、崩溃报告和屏幕错误无凭据、原始对话和内部秘密；
- App 内无任意 shell、任意 ROS、任意 SQL 或“忽略安全门”入口；
- 依赖、许可证、签名密钥和 release 构建做独立审查。

Family Product 上线前还需单独完成账号、云端、推送、短信、多方媒体、隐私政策和适用法律
评审；E1 局域网测试不能替代这些工作。

## 13. 缺陷严重度与发布阻断

| 级别 | 示例 | E1 APK 处理 |

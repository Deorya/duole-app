# 领域文档

工程技能在探索代码库时，应按以下规则读取本仓库的领域文档。

## 探索前需要读取

- 根目录的 `CONTEXT.md`
- 如果根目录存在 `CONTEXT-MAP.md`，则读取其中指向且与任务相关的各个 `CONTEXT.md`
- `docs/adr/` 中与当前工作区域相关的架构决策记录
- 多上下文仓库还需检查 `src/<context>/docs/adr/`

如果这些文件不存在，直接继续，不需要报告缺失或提前建议创建。生产者技能 `/grill-with-docs` 会在术语或架构决策明确后按需创建它们。

## 文件结构

本仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
├── dart/
└── flutter/
```

## 使用术语表中的词汇

输出内容涉及领域概念时，包括工单标题、重构建议、诊断假设和测试名称，应使用 `CONTEXT.md` 中定义的术语，不要改用术语表明确排除的同义词。

如果需要的概念尚未出现在术语表中，应重新检查是否正在创造项目没有使用的语言；如果确实存在领域缺口，则记录下来，留待 `/grill-with-docs` 处理。

## 标明与 ADR 的冲突

如果输出内容与现有 ADR 冲突，应明确指出，不要静默覆盖：

> 与 ADR-0007 冲突——但值得重新讨论，因为……
